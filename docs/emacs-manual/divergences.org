# ymacs Divergence Ledger

One entry per deliberate divergence from GNU Emacs, or additive surface
Emacs lacks. Each entry cites the Emacs manual node it relates to (node
names match the vendored corpus in this directory).Law:
[[file:spec-primitives.md][spec-primitives.md]] §6; manual markers cite
these numbers.

Format: number, status (planned/adopted), Emacs node, what and why, compat
cost.

* D1 — Discard duplicate completion interfaces [adopted]

- Emacs node: (emacs) Minibuffer / ido, helm, ivy, company, linum
- What: vertico/consult/orderless/marginalia/corfu are the blessed stack;
  ido/helm/ivy/company/linum load with a diagnostic instead of silently
  running.
- Why: one modern path beats four legacy ones; sane-choices directive.
- Compat cost: packages that hard-require the discarded interfaces fail
  loudly at load (intended).

* D2 — Configuration: init.org defaults + user.org overrides, theme
  tokens instead of faces [adopted; settings system shipped 2026-09-03]

- Emacs node: (emacs) Init File / Faces
- What: defaults are the shipped literate ~init.org~; user edits go ONLY
  to =~/.yggterm/ymacs/user.org~ (defaults ← overrides layering, VSCode
  settings design). Themes are a small closed token set with a bounded
  face→token shim; no per-face proliferation ships.
- Why: Emacs's unbounded face system is the largest source of visual and
  maintenance noise; a closed token set renders through yggterm themes.
- Compat cost: packages setting faces get tokens, not exact faces.
- ymacs extension: =M-x settings= renders the schema-declared settings
  (=init.org= =* Settings= chapter, org properties) as a dual-window UI
  (sections rail + settings document); changes write the =* Settings=
  drawer of =user.org= byte-preservingly. Sections ship with behavior
  (Editing first); empty sections are never rendered.

* D3 — Frames are yggterm rows [planned → primitives law §1.3]

- Emacs node: (emacs) Frames / Graphical Frames
- What: =make-frame= (=C-x 5 2=) spawns a new yggterm row (its own OSC
  7717 surface) attached to the same daemon, instead of an OS window.
  Remote frames are rows whose daemon is reachable over SSH.
- Why: ymacs lives inside yggterm; the row IS the frame unit the host
  already manages (titles, presence, attachment).
- Compat cost: frame-manager APIs that assume X/Wayland windows map onto
  row properties; exotic frame parameters are ignored.

* D4 — Window components: sidebar, palette, titlebar segments [planned →
  primitives law §1.2]

- Emacs node: (emacs) Windows / Split Window; (emacs) Buffers of
  =*Completions*=, =*Help*=
- What: additive window-scoped surfaces — the sidebar (content donated by
  the focused window's modes), the command palette (renders M-x and
  completing-read UIs), mode-claimed titlebar segments. =display-buffer=
  splitting remains honoured as parity fallback, but no ymacs facility
  requires stealing viewport.
- Why: Emacs pops and splits windows for UI that yggterm hosts as real
  surfaces; components keep the viewport for the user's text.
- Compat cost: none required of packages; UIs that assume a split-window
  completion buffer still work via fallback.

* D5 — Keyboard macros record command invocations, not key gestures
  [planned → primitives law §3]

- Emacs node: (emacs) Keyboard Macros
- What: the macro record is a sequence of executed commands with
  arguments; palette/sidebar interaction never enters the record; replay
  is headless-capable.
- Why: owner law — M-x through the palette must macro-replay with no
  problems; UI-gesture recording would couple macros to widget state.
- Compat cost: =insert-kbd-macro= emits the ymacs command-layer form
  (readable, portable to ymacs only) instead of raw key vectors.

* D6 — Durable buffers: every buffer is a file or a store row
  [adopted 2026-09-03 → spec-primitives §1.4]

- Emacs node: (emacs) Save Commands / Auto Save
- What: unnamed buffers are durably persisted to the profile store at
  creation and at every command — the scratch buffer survives kill -9.
  Auto-save loses its raison d'être: file-buffer drafts move into the
  store's drafts table.
- Why: no work ever lost is a product invariant, not a recovery mode.
- Compat cost: code assuming =*scratch*= content vanishes on restart
  breaks (it doesn't vanish); =auto-save-mode= hooks are no-ops.

* D7 — Profiles and the perpetual session [adopted 2026-09-03]

- Emacs node: (emacs) Exiting / Emacs Server
- What: Chrome-style profiles (=M-x sidebar/profiles=) — the open
  buffer set per profile, switchable without stopping the daemon. The
  daemon is perpetual: only =M-x save-buffers-kill-ymacs= ends it.
  =save-buffers-kill-emacs=-equivalent semantics, never triggered by a
  GUI restart or disconnect.
- Why: the multiplexer owns persistence; work loss by accident is the
  failure mode ymacs exists to remove.
- Compat cost: =kill-emacs= hooks run only on the explicit command;
  code expecting daemon exit on last-frame-close breaks.

* D8 — Info mode is a ymacs-native reader [adopted 2026-09-03, v0]

- Emacs node: (emacs) Info
- What: the forked manual ships as texinfo and is read in-editor by an
  Info-mode reader implementing the Emacs keyset (n/p/u/RET/l/q/s);
  the manual fork lives in docs/emacs-manual/ymacs/ (GFDL, ours) and
  upstream additions merge over time.
- Why: the manual must be readable where you work; the interface must
  match Emacs for portability of habit, diverging only toward
  modernism (recorded here per entry).
- Compat cost: v0 is a node navigator, not the full Emacs Info browser
  (indices, cross-ref completion and =Info-goto-node= completion are
  open work); Info files for the vendored corpus are readable by the
  external =info= reader meanwhile.

* D9 — The ribbon: tab-bar-mode and tool-bar-mode fuse into one strip [adopted 2026-09-04]

- Emacs node: (emacs) Tab Bars / (emacs) Tool Bars
- What: ymacs has ONE top chrome, the ribbon (docs/spec-ribbon.md): a
  tab strip pinned on yggterm's background chrome over a floating
  command panel. =tab-bar-mode= is THE switch for it, and
  =tool-bar-mode= is an alias of it — there is no separate icon tool
  bar and no Emacs-style window-configuration tabs; a ribbon "tab" is
  a command-group page (Home/Edit/View/...), not a saved window state.
- Why: the yggterm host renders one top strip per viewport; Excel's
  ribbon shape is the modernism ymacs adopts, and two modes gating one
  strip would be two encodings of one fact.
- Compat cost: Elisp that treats =tab-bar-tabs= as window
  configurations, or expects =tool-bar-mode= to toggle icons, breaks;
  the ymacs =tab-bar-*= API (add/remove tabs, groups, buttons) is the
  extension point instead.

* D10 — The startup screen shows on fresh boots, not every start [adopted 2026-09-10]

- Emacs node: (emacs) Initial Options / (emacs) Startup
- What: ymacs has a GNU-Emacs-style splash (*GNU Ymacs*): ASCII logo,
  version/copyright block, link bullets (The Ymacs Manual -> Info;
  Visit New File), TAB/S-TAB walk the links, RET activates the link on
  the cursor line, q leaves for the next real buffer; C-h r reads The
  Ymacs Manual from anywhere (Emacs habit, same binding). The screen
  is a read-only view buffer. DIVERGENCE: GNU shows it on every plain
  start and boot leaves *scratch*; ymacs's daemon is perpetual, so the
  screen shows on FRESH daemon boots only — a restored session is left
  untouched, and boot no longer force-opens docs/manual.org (the
  screen opens the manual: RET on its link, or C-h r / M-x info).
- Why: the Emacs welcome screen is the user's front door (owner
  request 2026-09-10, board ACK-83f10bee0f); with a perpetual daemon
  "every start" does not exist — the honest equivalent of GNU's plain
  start is a fresh daemon boot.
- Compat cost: Elisp expecting a manual file buffer selected after
  startup (the pre-D10 ymacs law), or =*scratch*= as the selected
  buffer on a plain boot, breaks; the extension points are
  =ymacs-splash-ensure= and the =startup-mode= keymap.

* D11 — Capable buffers render as prose by default [adopted 2026-09-10]

- Emacs node: (emacs) Text Display / (elisp) Faces
- What: a buffer whose major mode declares a rich parser (info-mode,
  org-mode today) renders through a CommonMark projection — the host
  markdown widget — when the buffer-local minor mode =rendered-mode= is
  on (=global-rendered-mode= arms it by default). Raw text is the minor
  mode off; typing in a rendered view drops to raw first (reading rich,
  editing raw). The buffer text stays the document: point, mark and
  undo live in the raw text always.
- Why: the owner asked for the manual (and org) to READ rich out of the
  box while the Emacs mode/knob vocabulary stays; decided via consult
  (gemini-3.8-flash-high) and docs/spec-rendering.md is the SSOT.
- Compat cost: elisp reading the buffer text gets the raw text (the
  projection is view-only, never written back); point-based commands in
  a rendered view act on node state instead of pixel position.

* D12 — The mode line lives in the ribbon strip [adopted 2026-09-10]

- Emacs node: (emacs) Mode Line
- What: the mode line renders as the ribbon strip label (mode names
  included) and the ribbon gains a Rendered/Raw toggle group on capable
  buffers; the strip ellipsizes instead of clipping (the shell-side
  max-width fix, lane/yggterm/prose-pane).
- Why: the host renders one top strip; a text modeline row would cost
  viewport height the ribbon already spends (owner directive 2026-09-10).
- Compat cost: elisp constructing mode-line strings has no reader; the
  ymacs surface is =rendering-mode-tag= + =rendering-ribbon-group=.
